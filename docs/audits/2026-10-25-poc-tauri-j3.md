## Constats

1. **La coexistence Tauri + STEP2 CUDA passe** sur cette machine : pic global
   2 392 MiB, marge 1 508 MiB, aucun OOM, aucun dépassement de 3 900 MiB.
2. **Le GUI n’est pas le facteur VRAM** : +2 MiB par rapport au bureau, contre
   +174 MiB pour Firefox. Le pic STEP2 est à ~2,2 GiB au-dessus de la baseline
   GUI, ce qui est cohérent avec les mesures du LOT-2 (~2,2 GiB).
3. **Le contrat des trois processus est stable** : `workflow-gui-tauri`,
   `WebKitNetworkProcess`, `WebKitWebProcess` sont présents à chaque
   échantillon, sans processus WebKit supplémentaire.
4. **Le CSV STEP2 est déterministe** sur les 5 runs : même SHA-256, malgré
   cinq processus CLI distincts.
5. **Le profil Firefox snap** impose un profil sous
   `/home/kidpixel/snap/firefox/common/` : `/tmp/opencode` n’est pas visible
   dans son namespace. Le profil est supprimé après la mesure.
6. **Aucun levier de contingence n’a été nécessaire**. Les niveaux
   `disable-dmabuf`, batch 4, cuDNN heuristique et batch 2/1 restent disponibles
   pour J4/J5 ou une autre machine.

## Limites

- Vidéo synthétique `testsrc2`, une seule scène : le run valide la VRAM et la
  stabilité, pas la parité de contenu STEP2.
- La VRAM est globale au GPU ; `pmon` ne donne pas la mémoire par processus
  sur cette GeForce. `fuser` et `query-compute-apps` servent d’attribution.
- Aucun run de contrôle Firefox + STEP2 n’a été fait : la comparaison Firefox
  porte sur la baseline sans inférence. Le gate VRAM reste absolu.
- Le profil `disable-dmabuf` n’a pas été nécessaire ; il reste validé par J2.
