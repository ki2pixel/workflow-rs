# Lot B2 — pilote `report_only` du détecteur YOLOX-Nano A2

> Statut : implémentation terminée et pilote exécuté sur les projets
> finalisés disponibles. Aucune activation de production, aucune
> modification de `a2.rs`, de `config/config.toml` ou du runtime.

## 1. Périmètre

Le lot B1 a validé le checkpoint époque 5 à 416 px : rappel D-060 95,5 %,
présence lower-third 96,7 %, boîte logo A2 91,7 %, open-set 90,3 %, FP
négatifs 3,3 % et 8,01 ms p95. Le lot B2 branche ce modèle dans le
post-traitement en **annotation seule** :

- aucune action, raison, confiance ou `scale_target` n'est modifiée ;
- `details.logo_detector` est ajouté aux décisions A2 ;
- toute erreur (modèle, verrou, OOM, décodage) laisse la décision intacte ;
- le mode est désactivé par défaut et le pilote tourne avec
  `post run --report-only` sur des copies.

## 2. Implémentation

### 2.1 Module `vision/logo_detector.rs`

- `DetectorConfig` : modèle, périphérique (`cuda`/`cpu`), runtime ONNX
  explicite, taille 416/640, seuils, classes et ROI (`full`, `bottom`,
  `bottom_left`).
- `LogoDetector::load` : session `ort` Level3, CUDA EP device 0
  (`CuDNNConvAlgorithmSearch::Heuristic`, TF32 désactivé), repli CPU
  uniquement si demandé explicitement ; validation de la forme d'entrée et
  de la sortie `[1, N, 5 + C]` ; warmup d'une frame 114.
- `detect` : BGR 0–255, letterbox 416 avec padding 114 et interpolation
  bilinéaire demi-pixel, NCHW, décodage YOLOX, score `objectness × classe`,
  NMS classe-aware, remap inverse en pixels source, filtres
  anti-boîte géante (`> 60 %` de la frame, largeur `> 80 %`, hauteur
  `< 2 px`) et rejet des centres dans le padding.
- Le module ne connaît ni `Decision`, ni `A2Options`, ni `CompMeta`.

### 2.2 Annotation `post/logo.rs`

- 12 timestamps uniformes, les mêmes que le gate OCR A2
  (`duration × (i + 0,5) / 12`), mais décodés séparément : `a2.rs` reste
  intact.
- Frames lues à la résolution source (1920×1080), pas sur la miniature
  480 px d'A2.
- Filtre A2 : centre dans la bbox du candidat A2 (marge 5 % en x, 10 % en
  y) ou dans les zones logo `x ≤ 0,40` avec `y ≥ 0,55` / `y ≤ 0,30`.
- Clusters temporels : IoU ≥ 0,50 et centre ≤ 10 px, persistance =
  frames distinctes / frames analysées, seuil 0,70.
- `details.logo_detector` expose `backend`, `model`, `model_sha256`,
  `input_size`, `roi`, `conf`, `iou`, `min_persistence`,
  `samples_requested`, `frames_analyzed`, `detections_total`,
  `detections_a2`, `clusters`, `logo` (détection dominante), `top`
  (trois premiers clusters) et `latency_ms`.
- `source_prior`, `source_logo_match` et `unknown_logo` comparent le
  cluster au prior D-052 quand il existe ; sans catalogue,
  `source_prior=false` et un logo persistant est marqué inconnu.
- `merged_with_lower_third` signale une boîte large (`> 35 %` de la
  largeur) qui recouvre majoritairement le candidat A2.
- Échec → warning et aucune clé ; le post continue.

### 2.3 Configuration

Sous `[steps.step8.post]`, désactivé par défaut :

```toml
a2_logo_detector = false
a2_logo_detector_model = "qa/logo_yolox_nano_a2.onnx"
a2_logo_detector_onnxruntime = ""
a2_logo_detector_device = "cuda"
a2_logo_detector_size = 416
a2_logo_detector_conf = 0.30
a2_logo_detector_iou = 0.65
a2_logo_detector_min_persistence = 0.70
a2_logo_detector_roi = "full"
```

`PostOptions` résout le modèle via `paths.models` et transmet le verrou
matériel (`hardware.lock_path`). La validation refuse device inconnu,
taille hors {416, 640}, seuils hors [0, 1] et ROI inconnue.

### 2.4 Verrou et runtime

- Le verrou `/tmp/workflow-rs-hw.lock` est acquis sans attente avant le
  chargement de la session et conservé pendant les 12 inférences ; la
  session CUDA est détruite avant de le relâcher.
- Si le verrou est occupé, le détecteur est ignoré avec un warning ;
  A2 reste inchangé.
- Le runtime CUDA est initialisé **avant** le gate OCR A2, sinon le
  `OnceLock` d'ONNX Runtime garderait le runtime CPU de production. Le
  pilote utilise
  `/mnt/venv_ext4/transnet_cv5_env/lib/python3.10/site-packages/onnxruntime/capi/libonnxruntime.so.1.23.2`
  et `LD_LIBRARY_PATH` avec les répertoires `nvidia/*/lib`.
- Le binaire ONNX reste hors dépôt ; le manifeste
  `assets/models/qa/manifest.toml` fige taille, SHA-256, licence, opset et
  point de fonctionnement.

## 4. ROI : mesures D-060

Le modèle B1 a été entraîné sur des frames 1280×720 letterboxées en 416
(échelle 0,325). En production 1920×1080 pleine frame, l'échelle tombe à
0,2167 : les petits logos perdent un tiers de résolution. Le recadrage
`bottom_left` (x ≤ 0,50, y ≥ 0,55) restaure une échelle proche de
l'entraînement. Mesures avec `training_yolo_b1/scripts/eval_roi_b2.py` :

| ROI | Références (200 boîtes) | A2 (60 boîtes) | FP négatifs |
| --- | ---: | ---: | ---: |
| `full` | **95,5 %** | 91,7 % | 3,3 % |
| `bottom` | 92,5 % | 90,0 % | 1,7 % |
| `bottom_left_50` | 84,0 % | **98,3 %** | 3,3 % |
| `bottom_left_45` | 84,0 % | 95,0 % | 3,3 % |
| `bottom_left_55` | 88,0 % | 98,3 % | 8,3 % |
| `bottom_left_40` | 68,5 % | 95,0 % | 1,7 % |

Le coin bas-gauche améliore fortement la boîte logo A2 mais dégrade les
références : le modèle a appris un contexte de scène que le recadrage
supprime. Le pilote B2 utilise donc `full`, seul point validé sur les deux
jeux. Une variante à deux passes (pleine frame puis coin conditionnel)
reste la piste B1.2, avec un budget de 2 inférences.

## 5. Pilote `report_only`

### 5.1 Corpus

Les bruts `.ecproj` sont supprimés par STEP7 après finalisation. Le pilote
ne peut donc utiliser que les projets dont le `.ecproj` `_assist` est
**byte-identique** au brut (SHA-256 égaux dans `audit.json`), preuve
qu'aucune transformation A1/A2/A6 n'a été publiée. Sur `/mnt/cache` :

- 15 projets finalisés avec `post.json`/`audit.json` ;
- 13 candidats fidèles (brut == assist, `apply = 0`) ;
- 2 projets exclus (`apply = 1` et `apply = 10`, assist transformé).

Le pilote demandé sur 20 projets est donc plafonné par le corpus
disponible ; les 13 candidats sont représentatifs de M6, Gulli et LMCR.

### 5.2 Protocole

`scripts/pilot-b2-logo-detector.py` :

1. copie les 13 `.ecproj` (petits) dans deux arbres `baseline/` et
   `detector/`, lie les vidéos et les fichiers `_ae.json`/`.csv` par
   symlink ;
2. construit deux configurations à partir de `config/config.toml` :
   baseline sans détecteur, détecteur avec les clés ci-dessus ;
3. exécute `workflow-cli post run --folder <arbre> --report-only` deux
   fois, avec le runtime CUDA et `LD_LIBRARY_PATH` ; les deux
   configurations forcent `a2_ocr_onnxruntime` sur le même runtime pour que
   le diff ne puisse pas venir d'une bibliothèque OCR différente ;
4. compare toutes les actions (code, action, target, reason, confidence,
   details hors `logo_detector`) et les compteurs `summary` ;
5. résume les annotations et écrit `pilot-b2.json`.

Aucune écriture sous `/mnt/cache` ; le work dir est
`training_yolo_b1/pilot_b2/`. Le résumé est copié dans
`results/b2-pilot.json` après retrait des chemins locaux et des noms de
fichiers vidéo ; les mesures ROI sont dans `results/b2-roi.json`.

### 5.3 Résultats

Run apparié : baseline et détecteur utilisent le même runtime OCR
(`libonnxruntime.so.1.23.2` du venv TransNet) et le même binaire
`workflow-cli`. Les deux runs sont `report_only`.

- **13/13** projets annotés, aucun audit `fail` ; **11 pass, 2 warn** `source_coverage` préexistants (report-only) ;
- **0 différence d'action** (`post.json`) et **0 différence de `review.json`**
  après retrait de `logo_detector` ; aucun `apply` créé ;
- **2/13** projets avec un logo persistant (11/12 frames, 91,7 %) ;
- **2/13** marqués `unknown_logo` (aucun prior D-052 pour M6) ;
- **100** détections brutes, **87** dans la ROI A2 ;
- aucun `wide` ni `merged_with_lower_third` : le détecteur a trouvé des
  logos compacts, pas des bannières ;
- latence détecteur par frame : p50 **9,28–10,86 ms** (médiane 10,69),
  p95 **10,77–12,25 ms** (médiane 11,27) ;

## 6. Limites

- Corpus de 13 projets, pas 20 : STEP7 ne conserve pas les bruts.
- Les projets M6/Gulli/LMCR n'ont pas de prior D-052 ; `unknown_logo`
  signifie « hors catalogue ou catalogue absent », pas « logo
  réellement inconnu ».
- Le détecteur ajoute **4,45 s par projet en moyenne** (12 décodages ffmpeg
  1080p + chargement de session). Une session partagée par lot et la
  réutilisation des frames OCR réduiraient ce coût ; l'inférence seule est
  ~0,12 s/projet.
- Le modèle reste mono-classe : `lower_third` n'est pas une classe
  séparée ; seule la boîte `logo` et sa largeur sont observées.
- **Fragmentation temporelle** : deux logos à 7/12 sont sous le seuil de
  0,70, dont un logo animé scindé en 7/12 + 3/12. Le clustering actuel
  (IoU 0,50, centre 10 px) est strict ; il privilégie la précision sur le
  rappel.
- Aucun cluster persistant n'a été observé sur les projets sans logo A2
  identifiable : les détections isolées (Gulli à 1/12, bord bas à 1/12)
  sont éliminées par la persistance. Cela ne prouve pas l'absence de faux
  positifs persistants sur un corpus plus large.
- La sélection du checkpoint sur D-060 et les fonds open-set M6 restent
  les biais documentés en B1.
- `report_only` ne prouve pas l'absence de faux `apply` en production ;
  il prouve seulement que l'annotation ne change aucune action sur ce
  corpus.

## 7. Décision

Le détecteur reste **désactivé par défaut**. Le pilote B2 est une preuve
d'observation, pas une autorisation d'`apply` : aucune exclusion OCR, aucun
recadrage et aucune modification de `a2.rs` ne sont introduits. La suite
(B1.2 ROI à deux passes, persistance sur corpus élargi, puis décision
d'activation) dépend des résultats du pilote et d'un retour opérateur.
